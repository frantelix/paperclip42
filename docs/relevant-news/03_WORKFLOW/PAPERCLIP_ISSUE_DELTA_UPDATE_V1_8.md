# Paperclip-Issue – Delta-Update V1.8

## Titel

Delta-Update-Testlauf V1.8 – [Datum] – [Mittag/Abend]

---

## Auftrag

Prüfe, ob seit dem letzten Briefing ein echtes, relevantes Delta vorliegt. Wenn nicht, erstelle eine No-Update-Notiz.

Kein Versand. Keine Automation.

---

## Aktive Grundlage

```text
relevant-news-v1.8
```

---

## Rollenfolge

1. CMO legt Run Mode fest und koordiniert.
2. Scout prüft neue Entwicklungen seit letztem Briefing.
3. Ranking Editor entscheidet Update / Watchlist / No-Update.
4. Source Verifier prüft neue Delta-Claims, falls Update.
5. Writer schreibt nur bei echtem Delta.
6. Reviewer prüft hart, ob das Update gerechtfertigt ist.
7. CMO meldet Status an CEO.

---

## Akzeptanzkriterien

- Keine Wiederholung des Morgenbriefings ohne neues Delta.
- Jedes Update enthält konkrete neue Entwicklung.
- Makro-/Daten-/Marktbewegungen sind nur Update, wenn sie eine konkrete Folge auslösen oder eine Top-Story wesentlich verändern.
- Keine Öl-/CPI-/PPI-/BIP-/Arbeitsmarkt-Wiederholung ohne neues praktisches Delta.
- Jeder neue Delta-Claim hat Source Verification.
- No-Update ist erlaubt und erwünscht, wenn nichts Starkes passiert ist.
- Datenqualität benennt, was bewusst nicht behauptet wird.
- Gelb/Rot blockiert.
- CMO bleibt Control Tower.
- CTO bleibt Technik.

---

## Stop-Bedingungen

- kein echtes Delta,
- neue Claims ohne Source Verification,
- Writer ergänzt neue Themen,
- Reviewer fehlt,
- Gelb/Rot ohne Korrekturticket,
- Versand/Automation geplant.
