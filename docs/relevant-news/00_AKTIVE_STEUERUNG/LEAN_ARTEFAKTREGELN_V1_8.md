# Lean-Artefaktregeln – relevant-news V1.8

V1.8 soll Qualität erhöhen, ohne den lokalen Test unnötig aufzublähen.

---

## Grundsatz

```text
So viel Dokumentation wie nötig, so wenig wie möglich.
```

---

## Empfohlene Größen

| Artefakt | Zielgröße |
|---|---|
| Candidate Pool | 40–60 gesichtete Leads, nur knapp gezählt/geclustert |
| Kandidatenliste | 25–35 ernsthafte Kandidaten, keine langen Exzerpte |
| Quellenbasis | 1 Zeile je Quelle, keine langen Exzerpte |
| Shortlist-Scorecard | Tier A/B/C + wichtigste Raus-Entscheidungen |
| Claim-Ledger | 1–2 Claims je Top Story; 1 enger Claim je Kurzmeldung |
| Source Verification | Top Stories vollständig, Kurzmeldungen mit Quellen-/Frischeanker |
| Briefing | Morgen 1200–1800 Wörter, Delta 200–450 Wörter |
| Review | 1–2 Seiten, klare Fehlercodes |
| Qualitätslog | 1 Seite, 1–3 Verbesserungen |

---

## Was nicht passieren soll

- keine 40 vollständig ausgeschriebenen Kandidaten ohne Pool-/Longlist-Trennung,
- keine langen Hintergrundaufsätze,
- keine endlosen Quellenexzerpte,
- kein Review mit viel Lob und wenig Entscheidung,
- keine 10 Verbesserungsmaßnahmen pro Lauf.

---

## Besser

```text
Kurze Tabellen, harte Entscheidungen, klare Stop-Regeln.
```
